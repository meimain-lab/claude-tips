# 侧边面板重做方案

对象：`pane/`（Claude 桌面应用里的速查面板，插件名 `tips-pane`）。菜单栏应用不在本方案范围内。

目标图：[design/side-pane-target-dark.png](design/side-pane-target-dark.png)。通用视觉规范见 [implementation-plan.md](implementation-plan.md) 第 5 节，硬性约束见第 2 节，两者继续有效。

## 1. 现在的问题

下面每一条都能在桌面应用的实际截图里看到，原因都在 `pane/hooks/register.tsx` 的画法上。

| # | 看到的现象 | 原因 |
|---|---|---|
| 1 | 每行只有一行字：中文说明和英文原文挤在一起 | 两段文字放在同一个 `Button` 里，中间用 `'\n'` 换行。桌面应用把 `Button` 画成原生按钮，换行被吃掉 |
| 2 | 英文原文在面板右边被直接切掉，没有省略号 | 文字没有设 `wrap`，一行放不下时既不换行也不截断 |
| 3 | 行首的灰色块宽窄不一，有的只剩一条细线 | 图标块是 `Box width={3}`，没有禁止收缩；行内文字太长时它被挤窄 |
| 4 | 图标是 `“`、`/`、`☆`、`·` 这几个字符，每组一个 | 用的是按分组取的字符（`GROUP_GLYPHS`），没有用每条提示自己的 `icon` |
| 5 | 分组标题、行、行与行之间没有层次，整体像一段纯文本 | `Text` 没有用 `size` 和 `weight`；行没有内边距、没有悬停样式；分组标题没有图标 |
| 6 | 「未整理」的行写成 `colab-h3-video /colab-h3-video`，同一个名字出现两次 | 这类行的标题和原文本来就相同，又被挤在一行 |
| 7 | 搜索框的占位文字和目标图不一致 | 占位文字写的是另一句 |
| 8 | 上一轮测试全过，但成品不合格 | 测试只检查元素树，没有人看过桌面应用里画出来的样子 |

## 2. 可用的元素

桌面应用的面板只能用宿主的元素：`Box`、`Text`、`Button`、`Input`、`Select`、`Svg`、`Link`、`Code`、`Markdown`、`Client`。`Client` 里能用的也是同一套元素，不能自己写网页。所以目标图要用这些元素拼出来，下面几项属性是关键：

- `Text`：`size`（`caption` / `footnote` / `body` / `heading` / `title`）、`weight`、`mono`、`dimColor`、`wrap`（含 `truncate-end`）。
- `Box`：带 `key` 时是悬停范围，`hover` 可以改背景色；`flexShrink`、`gap`、内边距、`borderStyle`、`backgroundColor`。
- `Button`：子元素只能是字符串和 `Text`，别的元素会被拒绝；桌面应用总是画成原生按钮。
- `Svg`：桌面应用可用，`width` 和 `height` 的单位是 CSS 像素；终端没有这个元素。
- `Input`：获得焦点时旁边会显示 `submitLabel`，去不掉。

类型定义在 `pane/.claude-plugin/types/claude-code/index.d.ts`（宿主加载 mod 后写出），不确定的属性先在那里查。

## 3. 先做一次试画（不提交）

这些元素在桌面应用里实际画成什么样，类型定义说不全。动手改之前，先在真实面板里并排画出下面几种行的写法，截图比较，选一种：

- **A**：一行是一个带 `key` 的 `Box`，里面左边是图标，右边是一列：第一行 `Button`（中文说明），第二行 `Text`（英文原文，等宽、次要色、`truncate-end`）。
- **B**：同 A，但第二行也是一个 `Button`，和第一行触发同一个动作，这样点英文也有效。
- **C**：整行是一个 `Button`，里面两个 `Text`，看桌面应用有没有办法让它们分两行。

要回答的问题：哪种写法能稳定地显示成两行、左对齐、过长时出省略号；悬停背景是否生效；`Svg` 图标的大小和对齐是否可控；`Box` 的 `width` 数值在桌面应用里按什么单位算。

试画的结论写进本文件第 7 节，然后再做第 4 节。

## 4. 目标画法

**整体**
- 从上到下：搜索框、「直接说」「斜杠命令」「我的」三组、有内容时的「未整理」、底部的提示行（文件读取出错时）。
- 面板窄到约 320 像素、宽到约 700 像素时都不能出现被切掉的文字：放不下的一律用省略号截断。

**搜索框**
- 占位文字：`搜一下：画图、定时、交接`。
- 边打字边过滤；`submitLabel` 用一个短词。

**分组标题**
- 一行：分组图标、分组名、条数。分组名用 `footnote` 大小、半粗、次要色；条数用次要色。
- 分组之间留出明显间距，分组内的行间距更小。

**行**
- 行首是图标块：固定大小、不收缩，中性色底，里面是这条提示自己的图标。
- 右边两行字：第一行中文说明，`body` 大小、常规或中等字重；第二行英文原文，`footnote` 大小、等宽、次要色。两行都是 `truncate-end`。
- 悬停时整行换背景色。刚填入的那一行用强调色底、反色文字，行尾显示 `已填入`（没有输入框可填时是 `已复制`），约 1.6 秒后恢复。
- 条目引用的 skill 已不存在时，整行变灰，行尾显示 `已不存在`。
- 点第一行或第二行都要触发填入。

**图标**
- 内容文件里的 `icon` 是 SF Symbols 的名字，SF Symbols 不能随仓库分发。在 `pane/hooks/` 里加一张对照表：每个用到的名字对应一段自己画的或取自 Lucide（ISC 许可）的 SVG 路径。用了 Lucide 的话，在仓库里加上它的许可说明。
- 对照表至少覆盖 `content/tips.json` 和示例文件里出现的全部名字，以及这四个常见的：`note.text`、`arrow.triangle.branch`、`tag`、`paperplane`。表里没有的名字，退回到该分组的图标。
- 图标只用一种中性灰，在深色和浅色主题下都要看得清。如果宿主能告诉 mod 当前是深色还是浅色，就按主题取色；不能就选一个两边都能读的灰。
- 终端没有 `Svg`：保留现在的字符图标，但图标块固定宽度、不收缩。

**「未整理」**
- 第一行是 skill 名，第二行是这个 skill 自己的描述（取第一句，截断成一行，不用等宽字体）。点行填入的仍是 `/skill 名`。

**不改的**
- 读文件、合并、搜索排序、skill 扫描的逻辑（`tips-core.ts`）不动，除非画法需要新的字段。
- `/tips` 的开关方式、`$.prompt.fill` 的用法、不向模型上下文加任何内容，这三点不变。

**可选（前面都做完、且改动很小时再做）**
- 行尾加一个小按钮，点开后在该行下面显示这条提示的中文详情（`detail`），再点收起。做不做、为什么，写进汇报。

## 5. 验收

1. **看真实画面**：在 Claude 桌面应用里打开面板，深色和浅色各截一张，面板较窄和较宽各截一张，和目标图逐项对比。截图要自己看过，汇报里说明和目标图还差在哪里。只看元素树不算验收。
2. 如果实现会话自己打不开面板，就给用户派一个一步的任务（在那个会话里输入 `/tips`），然后再截图。
3. 实测：`/tips` 能开关；打字能过滤；点一行后英文出现在输入框，行尾显示 `已填入`；悬停有反馈。
4. `claude plugin validate pane`、类型检查、`claude plugin test pane` 通过。测试要覆盖：每行是两行结构、图标对照表覆盖内容文件里的全部名字、未知图标名退回分组图标、「未整理」行的第二行是描述。
5. 再确认一次没有进入模型上下文：只允许有 `session.start`（注册命令）、`command.run`、`ui.render` 这三类钩子，`/tips` 不向对话返回文字。
6. 终端里的画法不能比现在差：在终端会话里打开一次，确认图标块等宽、文字不乱。做不到实测就在汇报里写明。

## 6. 提交与安装

- 在 `main` 上提交，提交信息用英文；本文件随第一个提交一起进仓库。不要推送。
- 提交前检查 diff，不能有姓名、邮箱、公司名、本机路径。
- 注意：用户的电脑上现在同时有两份面板，一份是从 GitHub 安装的 `tips-pane@tips-cheat-sheet`（旧画法），一份是实现会话里热加载的开发副本。实测时确认看到的是哪一份。安装版的更新（推送后运行 `claude plugin update`）由发起会话在用户同意推送之后做，实现会话不要动用户的插件配置。

## 7. 试画结论

两轮试画都在 Claude 桌面应用（引擎 2.1.321）的真实面板里截图比较。

**选了 A**：第一行中文说明是 `Button`（`plain`），第二行英文原文是 `Text`（等宽、`footnote`、次要色），两行都 `truncate-end`。
- A 能稳定画成左对齐的两行，过长时出省略号。
- B（第二行也用 `Button`）也能分两行，但 `Button` 里的 `Text` 不认 `mono`，英文变成比例字体，和目标图不符。
- C（整行一个 `Button` 放两个 `Text`）在桌面应用里被画成一行，两段文字连在一起、被直接切掉，正是现在的毛病。
- 代价：英文那一行点了没有反应，只有中文那一行能触发填入。宿主没有能放等宽文字、又能点的元素，`Box` 也没有 `onPress`。

**和预想不同的地方**
- `plain` 的 `Button` 在桌面应用里不画原生按钮外框，但标签文字比普通 `Text` 往右缩进约 6pt。给第二行套一个 `paddingLeft="xs"` 的 `Box`，两行正好对齐。
- `Button` 里的 `Text` 只认颜色和截断：`mono`、`weight` 都被忽略，所以中文说明只能是常规字重。
- `Box` 的 `width` 按“格”算，桌面应用里一格约 8.75pt；行高一格约 20pt。图标块不适合用 `Box` 宽高拼。
- `backgroundColor="subtle"` 在深色主题下是一块很亮的灰，会盖住灰色图标。
- `Svg` 按给定的 `width`、`height`（CSS 像素）原样画，不会被挤窄。所以图标块整个画成一张 32×32 的 SVG：圆角底色和图标在同一张图里，底色用半透明中性灰 `rgba(142,142,147,0.18)`，线条用 `#8E8E93`，深浅两种主题都看得清。
- 宿主不告诉 mod 当前是深色还是浅色，所以图标颜色只能选两边都能读的中性灰。
- 主题色 `suggestion` 在窗口处于前台时是系统强调色（蓝），窗口不在前台时变成浅灰；`inverseText` 在深色主题下是深色字。所以选中行的文字和图标直接用白色，不用 `inverseText`。
- `Box` 的 `hover` 接受原始颜色，悬停底色用和图标底同一种半透明灰。悬停效果要靠鼠标在真实窗口上移动才能看到，截图时另行确认。
- `caption`、`footnote`、`body` 在面板里字号差别很小。
